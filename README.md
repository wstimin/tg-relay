# TG Relay

Telegram 专用代理，单个 Go 进程同时运行 MTProto Fake TLS 内核、管理 API 和内嵌 Web 面板。无需 sing-box、Xray、Node.js 运行时或外部数据库。

## 转发关系

```
Telegram 用户 → 入站（独立用户密钥） → 路由规则 → 直连 / SOCKS5 / HTTP / HTTPS 落地 → Telegram DC
```

- 用户分配入站，路由按入站 ID 匹配，不按用户分配出口。
- 优先级数字越小越先匹配；相同优先级按规则 ID 排序。
- 路由可以明确选择“直连 Telegram”，使用入站服务器本机网络；也可以指定 SOCKS5 / HTTP / HTTPS 落地。
- 未匹配规则或匹配出口停用、连接失败时拒绝连接，不自动回落到直连规则。只有明确选择直连的规则才会直接连接。
- 保持公开入口、端口、Fake TLS 域名和用户密钥不变，调整路由或落地不会改变 TG 链接。
- 平滑切换：新连接走新出口，旧连接继续走旧出口；旧落地必须继续运行。
- 立即切换：断开转发关系变化的连接，Telegram 自动重连。停用用户或入站始终关闭对应已有连接。

## 本机启动

Windows 在项目目录运行：

```powershell
.\start.ps1
```

打开 http://127.0.0.1:8765 ，自行创建管理员。没有默认密码。首次设置只允许本机访问，密码最低 6 字节，支持 6 位数字。

新建入站时选择 **直连 Telegram / 经指定落地转发 / 稍后配置路由**。选择直连或落地时，入站与独立路由一起保存，失败整体回滚；稍后配置会明确显示“待配置”，此时不能连接。接着创建用户并分配入站，再分发用户专属链接。已有入站可在“路由管理”里选择直连或落地，不需要重新分发链接。入站监听端口需要在服务器防火墙及云安全组放行。公开入口必须填写用户可访问的真实地址。

Fake TLS 域名填写真实存在、经所选路由可访问的 HTTPS 主机。服务器时钟需要准确。无需为每个入站申请 TLS 证书；Fake TLS 是 MTProxy 传输伪装，不是面板 HTTPS。

## 表单和连接排查

- 表单不会因误点遮罩而关闭。关闭、取消、Escape 或切换面板页面时，有未保存的修改会提示继续编辑、保留草稿或放弃修改；保存失败保留原输入。
- 草稿只存本次登录的浏览器内存，不写浏览器持久存储；退出登录或会话失效时清除。刷新、关闭页面前会提示，刷新后无法恢复。落地密码不会因草稿功能写入 localStorage。
- 节点详情使用居中弹窗；标签切换保留原遮罩和弹窗外壳，避免重复入场动画，支持方向键 / Home / End 切换。滚动条预留空间避免开关弹窗时横向跳动。面板设置的未保存修改不会被定时刷新覆盖。
- 端口占用时会明确提示更换空闲端口。面板与 TG 入站不能占用相同的监听地址和端口。新入站默认端口跳过当前面板 URL 端口及已配置入站端口，其他进程是否占用仍以真实监听结果为准。
- “TG 代理链接”会说明入站停用、用户或凭据无效、缺少路由、公开入口为内网地址等本地配置问题。提供 `tg://proxy` 链接与 `https://t.me/proxy` 打开方式。Fake TLS 密钥使用 `ee + 16 字节密钥的十六进制 + 域名的十六进制`。
- “测试当前线路”经当前选中的直连或落地路径，分别测试 Telegram DC 与伪装域名的 TCP 443；结果是服务器侧 TCP 检查，不等于公网入口可达、完整协议握手或真实客户端连接成功。防火墙、安全组、NAT 映射、DNS 与服务器时间仍需检查。

## 界面外观

浅色 / 深色统一使用「瓷白＋墨青」设计：浅色以瓷白、矿物灰和深青为主，深色以石墨灰、柔和青绿和明亮文字分层。整站只有一份语义主题样式，右上角切换后记住选择；优先使用系统中文字体。导航、指标、表格、登录、设置及居中弹窗共用字体、间距、圆角和状态颜色。

入站和路由页展示「TG 入站 → 独立路由 → 直连 / 落地」结构；节点表格合并展示用户与连接数，保留管理、路由和用户链接操作。数据全部来自运行状态，不写入设计图中的示例指标。手机端结构图自动纵向排列，表格在自身容器内横向滚动；登录页收紧介绍区域，让账号、密码和登录按钮优先可见。

卡片在鼠标悬停时轻微抬升，按钮提供按压及真实提交中的加载反馈；弹窗入场仅播放一次，标签切换不重复播放。系统启用减少动态效果时关闭动画和悬浮位移，键盘操作保留清晰焦点。

## Linux 部署

支持 systemd Linux amd64 / arm64。纯 Go 构建，无 CGO 运行库依赖。在服务器 SSH 终端执行交互式安装器：

```sh
curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/wstimin/tg-relay/main/install.sh | sudo bash
```

安装器从 GitHub Releases 下载对应架构的发布包，并校验 SHA256。它会询问面板端口、访问方式和管理员用户名及密码；密码隐藏输入，通过标准输入初始化，不写入命令行参数或 systemd 配置。默认只监听回环地址，建议通过 SSH 隧道管理。公网 HTTP 方式会明确提示风险；也可以选择已有 HTTPS 反向代理。

安装器支持通过上述管道执行，也支持下载到文件后执行。脚本检查包含文件执行、标准输入执行和被其他脚本加载三种入口，避免管道模式下 `BASH_SOURCE` 未定义导致无法启动。

选择公网 HTTP 时，优先使用 SSH 连接中的服务器公网 IPv4；没有可用地址时，通过 HTTPS 查询 [ipify](https://www.ipify.org/)，超时上限 4 秒。识别结果作为默认值，回车确认或手动修改。识别失败时允许手动输入并重试；更新时保留已有域名。多 IP 或 NAT 环境请确认填写的是实际可访问的入站地址。

安装成功后运行 `sudo tg`（root 直接运行 `tg`）打开循环交互菜单；完成操作或遇到错误后均可返回菜单：

| 选项 | 功能 |
| --- | --- |
| 1 | 首次安装询问设置；已有安装直接更新，保留端口、账号密码、证书及代理数据 |
| 2 | 查看面板地址、端口和实际管理员用户名 |
| 3 | 修改端口、IP、域名和访问方式 |
| 4 | 重置管理员账号和密码，用户名可保持不变 |
| 5 / 6 / 7 | 启动 / 停止 / 重启服务 |
| 8 | 查看状态和最近日志 |
| 9 | 域名证书申请、已有证书导入、续期及证书状态 |
| 10 | 启用 / 关闭开机自启 |
| 11 | 卸载程序，保留数据库、证书及 ACME 账户 |

管理员密码最低 6 字节，安装、重置和网页登录使用同一套校验。新账号保存后安装器会通过标准输入再次校验，不输出密码。网页登录自动忽略用户名两端空白，密码中的空格和特殊字符保留原样。重置账号密码会立即撤销旧管理会话并解除旧凭据的失败锁定，不更改 TG 用户、密钥、路由或累计流量，也不需要重启服务。

从旧版本升级：先获取本仓库最新安装脚本，选 **1 安装 / 更新**。已有安装不再询问端口、访问方式、用户名或密码，保留原配置和证书；修改设置请单独选择 **3**，账号恢复请单独选择 **4**。升级完成后也可随时运行 `tg`。更新和卸载会保留数据库；重启、停止服务以及应用新的面板监听配置会断开已有 TG 连接，链接不变，Telegram 可重新连接。

每个 Release 提供 Linux amd64 / arm64、Windows amd64 二进制包及 SHA256 校验文件。发布流程支持版本标签触发，也可以在 GitHub Actions 中手动选择已有版本标签发布。

默认面板仅监听回环地址；通过 SSH 隧道完成首次设置及日常管理：

```sh
ssh -L 8765:127.0.0.1:8765 your-user@your-server
```

然后在本机打开 http://127.0.0.1:8765 。systemd 单元允许监听低端口，实际能否使用仍取决于端口占用及服务器网络规则。

### 面板版本与一键更新

页面左侧和页脚显示当前 Go 进程的构建版本；版本由 Release 标签编入二进制，`tg-relay -version` 输出相同值。本地源码构建默认显示“开发构建”，不冒充正式版本；手动构建可使用 `go build -ldflags '-X main.buildVersion=vX.Y.Z'`。

管理员登录后检查 GitHub 最新正式版；发现新版时显示入口。也可在 **面板设置 → 版本与更新** 手动检查和查看发布说明，选择一键更新并确认。已检查结果短暂缓存，检查失败会显示错误，不会报告为最新。仅允许更新至刚核对过的更高正式版本，不安装草稿、预发布版或降级。

无需手填版本号，界面显示当前版本与自动识别的目标版本。确认后立即显示更新进度，依次呈现等待、下载、校验、安装重启、运行确认；下载源提供文件总大小时按实际字节显示百分比，否则显示不定进度，不估算整体完成百分比。关闭进度弹窗后可从顶栏或设置页再次查看。重启断线时自动重试，确认目标版本、服务就绪和任务完成后自动刷新至新版登录页；失败保留原因，不冒充成功。更新期间暂停配置编辑，已有未保存草稿需先处理。

`tg` 菜单仅在实际安装、证书或服务修改操作期间占用更新锁，停在菜单等待输入不阻塞网页更新。旧脚本已打开的菜单仍会保持原来的锁，升级前请选 0 退出；获取最新安装脚本后选 1 即可自动更新最新正式版。命令行显示下载进度并核对解包后二进制的实际版本，已有设置不重填。显式 `--version` 只用于本次安装操作，后续菜单更新恢复自动获取最新版本。

一键更新适用于通过本安装器部署的 Linux amd64 / arm64 systemd 服务。面板仍以普通 `tg-relay` 账号运行；`tg-relay-update.path` 由 systemd 监视更新请求，按需启动 root 更新任务，不增加常驻应用进程。更新与命令行安装器使用同一把锁，避免同时替换文件。

更新任务仅访问固定 `wstimin/tg-relay` 正式发布源，下载时校验 HTTPS、SHA256SUMS 及发布元数据摘要（存在时）。限制文件大小、解包文件白名单，拒绝符号链接、路径穿越、重复项，核对新二进制架构及版本。下载和校验阶段保持原服务运行，通过后才替换原程序及配套服务文件，配置、数据库、密码、密钥、配额、累计流量及证书不重设。启动后检查实际版本、面板响应和启用入站监听；失败恢复本次更新前的程序文件并重新启动，临时更新文件清理。自动更新不迁移数据结构，因此当前恢复只替换程序文件，不还原或覆盖数据库。

更新重启会短暂断开 TG 连接，链接保持不变；管理会话会失效，需要重新登录。网络或校验失败时不停止原服务。任务状态和失败原因显示在面板；较长时间无结果时，服务器运行 `journalctl -u tg-relay-update -n 80 --no-pager` 检查。磁盘损坏、断电、强杀更新进程等不能保证自动恢复，请保留正常备份。

旧版本没有上述更新组件，**首次启用此功能仍需执行一次新版安装脚本**；不能只用旧的 `tg` 脚本期待出现新功能。此后有新版可从面板更新，不再填写任何安装设置。Windows 或手动部署能查看版本及检查新版，但不会伪装为已支持 systemd 一键更新。

### 公开入口与 Fake TLS 域名预设

新建入站自动建议当前面板地址；本机访问时优先取已配置的公开入口或面板地址，再由服务器以 4 秒超时查询 ipify 公网 IP。字段旁提供“自动识别 IP / 域名”按钮和来源提示，查询失败保留手工输入；异步结果不会覆盖用户刚填写的内容。只能推断候选地址，无法自动识别你尚未配置的自有域名；多 IP、NAT、CDN、反向代理环境必须核对实际 TG TCP 入口。

在 **面板设置 → Fake TLS 域名预设** 中每行填写一个域名，最多 32 项，第一项作为新入站默认值；留空恢复内置候选。入站表单可以下拉选择，也可以选择手动填写或直接修改域名。保存候选列表不会修改已有入站的伪装域名或链接。预设不代表已实测可用，仍可通过链接视图的当前线路检查验证服务器侧 TCP。

### 面板域名与证书

安装时的访问方式包括本机隧道、公网 HTTP、自动申请域名 HTTPS、已有 HTTPS 反向代理。也可在 `tg` 的 **9 证书管理 → 1** 中为已安装面板启用 HTTPS：

1. 将你拥有的域名 A 记录解析到服务器；错误的 AAAA 记录需要修正。输入域名后，安装器显示 DNS 解析结果供确认。
2. 放行公网 TCP 80 供 HTTP-01 验证，并保持该端口空闲；选择另一个端口（例如 443）作为 HTTPS 面板端口。安装器不会停止占用端口的其他程序。
3. 按提示提供证书账户邮箱并确认 CA 条款。安装器仅在需要时从系统软件仓库安装 openssl / socat，使用固定版本且校验 SHA256 的官方 [acme.sh](https://github.com/acmesh-official/acme.sh) 申请 Let's Encrypt 证书。
4. 证书检查通过后，由同一个 Go 服务直接提供 HTTPS，无需额外运行 Nginx。已有程序可以从证书菜单导入完整 PEM 证书链与无口令私钥；导入时检查域名、有效期和密钥是否匹配。

自动申请的证书由 `tg-relay-renew.timer` 每日检查，申请和续期都需要 TCP 80 可用；可以在证书菜单手动检查续期。证书与私钥位于 `/etc/tg-relay/tls`，私钥仅 root 与服务组可读，ACME 账户位于权限为 0700 的 `/etc/tg-relay/acme`。续期证书热加载，无需重启 TG；替换中的不完整证书或域名不匹配时保留内存中上一份有效证书。导入的外部证书由其原签发方式续期，再重新导入。

申请失败或取消不会应用新的面板访问配置；新监听配置启动失败时恢复原配置。域名证书针对管理面板；TG Fake TLS 域名与面板证书独立，TG 入站仍为独立 TCP 服务，不能套普通网页 CDN 或仅 HTTP 的反向代理。多 IP / NAT、DNS 传播和安全组规则仍需在实际服务器确认；本仓库测试不代表真实 CA 签发或服务器可达性验证已完成。

已有 HTTPS 反向代理时选择访问方式 4，代理应保留原始 Host 并转发到回环监听端口。手动启动也支持 `-tls-cert /path/fullchain.pem -tls-key /path/key.pem -admin-host panel.example.com`，密码恢复命令的密码始终通过标准输入传递。

## 数据与计量

- 数据目录默认 `data`，SQLite 文件 `tg-relay.db`。密码使用加盐 PBKDF2-SHA256 保存；落地密码及 TG 密钥需要用于连接，存于数据库中。
- 用户配额跨入站累计，上下行均计入；0 为不限量。到期、停用、撤销凭据和额度耗尽会阻止转发并回收连接。
- 计量口径是成功写入的代理数据流，不包含 TLS、TCP、代理握手等网络开销。不是云厂商带宽账单口径。
- 流量约每 2 秒落库，正常退出会最终保存。断电或强杀可能丢失尚未持久化的计量，不能作为严格财务计费系统。
- 完整恢复：先正常停止服务，复制整个数据目录，恢复后用同一数据目录启动。不要只复制运行中的主数据库而忽略 WAL。
- 面板 JSON 导出包含配置、用户密钥、落地密码和累计流量，不含管理员密码；当前没有 JSON 导入功能，完整备份请用上述数据目录方式。
- 每个数据目录只启动一个实例。管理员会话保存在内存中，重启后需重新登录。

## 构建及验证

开发使用 Go 1.26 或更高版本：

```sh
go test ./...
go vet ./...
go build -trimpath -ldflags '-s -w' -o bin/tg-relay .
```

测试使用本机回环直连、模拟 SOCKS / HTTP 出口和协议握手，覆盖原子创建入站与路由、直连配置排他验证、禁止故障自动直连、线路探测路径、链接格式与配置警告、多密钥、转发、平滑及立即切换、链接稳定、停用断连、并发配额、配置保存失败回滚、权限与持久化。`browser_test.go` 是显式启用的临时浏览器测试环境，不进入正式二进制。

当前尚未用真实 Telegram 客户端和实际服务器链路验证兼容性、延迟、吞吐及长期稳定性，不能承诺“秒连”或比 sing-box 更快、更省内存。出口测试只验证到一个 Telegram DC 的 TCP 隧道，不代表全部 Telegram 功能可用。DC 地址使用静态种子，未实现自动更新。SOCKS5 / HTTP 落地本身不提供额外链路加密；需要加密连接到落地时选择 HTTPS 代理。
